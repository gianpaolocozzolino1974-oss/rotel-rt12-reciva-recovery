# Checklist prima di pubblicare su GitHub

- [x] Nome pubblico approvato: **Gianpaolo**. Non pubblicare il cognome.
- [ ] Decidere se pubblicare la fotografia del dispositivo. Mostra una stazione in riproduzione e l'impianto domestico; non è necessaria alla riproduzione tecnica.
- [ ] Controllare il repository per username macOS, numeri di serie completi, IP pubblici, password o token. **Non caricare il contenuto intero della cartella Downloads**.
- [ ] Confermare che **non siano inclusi** firmware `.bin`, wrapper Rotel `.tar.bz2`, eseguibili `firmware_upgrade` o pacchetti installativi modificati; i link puntano soltanto alle fonti Rotel.
- [ ] Verificare i link dei file Rotel: potrebbero cambiare o essere rimossi nel tempo.
- [ ] Chiarire che **un solo RT-12** è stato recuperato, e che la variante portabile non è stata provata su un secondo apparecchio.
- [ ] Scegliere una licenza per **il codice originale del progetto** (es. MIT) e, separatamente, una per i testi e le immagini. Non applicare una licenza proprietaria ai file Rotel.
- [ ] Creare il repository `rotel-rt12-reciva-recovery` su GitHub e caricare **solo** i file contenuti nella cartella del progetto.
- [ ] Controllare l'anteprima del README e della foto prima di rendere il repository pubblico.
- [ ] Sostituire `[LINK_GITHUB]` in [PUBLICATION-POSTS.md](PUBLICATION-POSTS.md) con il link reale, dopo la pubblicazione.
- [ ] Pubblicare inizialmente in uno o due forum dedicati e raccogliere conferme da altri proprietari prima di dichiarare supporto ad altri modelli.
